# PLAN-012: 레이아웃 일관성과 마이크로인터랙션

> 상태: P0·P1 구현 완료 (2026-10-23)
> 역할: 현재 화면의 공백·컨트롤 크기·버튼 위계를 정리하고, 그 위에 마이크로인터랙션과 피드백을 적용한 기록
> 상위 문서: [화면과 흐름](../frontend.md), [디자인 시스템](../design-system.md)
> 관련 문서: [ADR-021](../decisions/ADR-021-microinteractions.md), [PLAN-010](PLAN-010-registration-ux.md)

## 1. 배경

P0·P1에서 등록·재고·공유·검색 화면이 빠르게 늘어나면서 컨트롤 높이와 페이지 간격이 갈라졌습니다. Playwright로 모바일 390px·데스크톱 1280px·라이트/다크 화면을 캡처해 확인한 문제는 다음과 같습니다.

| 영역 | 확인한 문제 |
|---|---|
| 컨트롤 | `sm` 버튼 36px, 검색 필터 28~36px, 닫기 36px, 기본 입력 48px가 혼재 |
| 간격 | 페이지 루트가 `gap-5`와 `gap-6`으로 갈라지고 카드 패딩이 12px/16px로 혼재 |
| 폼 | 데스크톱 편집 폼이 960px까지 늘어나 한 줄 입력이 지나치게 넓음 |
| 검색 | 데스크톱 결과 카드가 한 열로만 쌓여 공간을 낭비하고, 필터가 작은 버튼으로 흩어짐 |
| FAB | 검색·공유·설정·카테고리 화면에서도 FAB가 콘텐츠를 가림 |
| 상세 | 모바일 재고 상세에서 상태·이동·삭제가 이동 이력 아래에 있어 스크롤이 과도함 |
| 피드백 | 상태·이동·삭제·편집 저장·계층 CRUD·카테고리 변경에 성공 확인이 없거나 화면마다 다름 |
| 모션 | 버튼의 이동은 `translate`가 transition 대상이 아니어서 즉시 튀고, 그림자만 사라짐 |

## 2. 레이아웃 결정

- 컨트롤 높이를 `44px(보조) / 48px(기본) / 56px(FAB)`로 고정했습니다.
- 페이지 루트는 `gap-6`(24px), 카드 본문은 `p-4`(16px)로 통일했습니다.
- 편집·카테고리 폼은 데스크톱 `max-w-2xl`(672px)로 제한했습니다.
- 검색 필터는 44px 컨트롤을 담은 테두리 툴바로 묶고, 데스크톱 결과는 masonry 2열로 배치했습니다.
- FAB는 홈·공간·재고 목록에만 표시합니다. 검색·공유·설정·카테고리·상세·편집에서는 숨깁니다.
- 재고 상세의 상태·위치·관리 카드를 이동 이력보다 위에 배치해 모바일 동작 우선순위를 맞췄습니다.
- 이미지가 1장일 때 갤러리 카드를 4:3 대형 이미지로 키우고, Room·Shelf 상세의 “공유” 버튼을 헤더 우측으로 옮겼습니다.
- 카테고리 행의 이름 변경·병합·삭제는 모바일에서 아이콘 버튼(44px)으로 표시하고 데스크톱에서 라벨을 함께 표시합니다.

## 3. 마이크로인터랙션 결정

- 모션 토큰은 `90ms press / 140ms fast / 180ms enter / 240ms sheet / 120ms exit`와 `ease-snap`, `ease-out`, `ease-in`을 사용합니다.
- 버튼은 그림자 바깥 모서리가 고정되도록 `hover -1px/+5px`, `active +2px/+2px`로 움직입니다. FAB는 `active +4px/0`입니다.
- 포커스는 primary가 아니라 전경색 3px + offset 3px로 표시합니다. 크림 배경에서 primary 링의 2.68:1 대비를 피합니다.
- 대화상자·시트는 `data-state=open`에서 180ms/240ms로 등장하고, overlay는 140ms 페이드합니다.
- 카드와 목록 행은 hover에서 1px 상승·섀도 6px, press에서 1px 하강합니다.
- 토스트는 `@radix-ui/react-toast`로 구현했습니다. 성공·정보는 polite, 오류는 foreground로 즉시 알립니다. 성공 5초·오류 8초, hover/focus/blur 일시정지, F8, 44px 닫기 버튼을 제공합니다.
- `prefers-reduced-motion: reduce`에서는 이동·슬라이드·스케일과 토스트 애니메이션을 제거합니다.

## 4. 피드백 적용 범위

| 화면 | 적용 |
|---|---|
| 재고 상세 | 상태 변경·이동·삭제 토스트 |
| 재고 편집 | 저장 후 상세 이동 + 토스트 |
| 물건 편집 | 저장 후 상세 이동 + 토스트 |
| 공간 지도 | Room/Shelf/Box 생성·수정·이동·삭제 토스트 |
| 카테고리 | 생성·이름 변경·삭제 토스트, 병합은 기존 인라인 유지 |
| 공유 | 초대·수락·거절·권한 변경·철회 토스트 |
| 세션 만료 | 오류 토스트 + 로그인 이동 |
| 등록 시트·설정·공유 대화상자 | 기존 인라인 성공 상태 유지 |

## 5. 검증

- Vitest 36개, Playwright E2E 24개(axe 접근성 12개 포함), `tsc --noEmit`, `vite build`가 통과합니다. 재고 상세 테스트에 상태 변경 토스트 확인을 추가했습니다.
- Playwright로 390×844, 1280×900, 라이트·다크의 주요 화면을 캡처했습니다.
- Playwright로 다음을 확인했습니다.
  - 버튼 hover `-1px / 5px`, active `+2px / 2px`, transition에 `translate` 포함
  - FAB hover `6px`, active `+4px / 0`
  - 검색창 form focus-within 3px 링 + 6px 섀도
  - 카드 hover 1px 상승 + 6px 섀도
  - 시트 `sheet-in` 240ms, overlay `overlay-in` 140ms
  - reduced motion에서 시트·overlay·토스트 `animation: none`
  - 토스트 352px, 모바일 FAB 없음 72px / FAB 있음 144px, 데스크톱 우하단 24px
  - 성공 토스트 `aria-live=polite`, 오류는 foreground
  - 토스트 닫기 시 `data-state=closed` → 120ms `toast-out` → DOM 제거
  - 업로드 XHR 진행률 `role=progressbar`와 퍼센트 표시
  - 검색 결과는 `<ol aria-label="검색 결과">`로 DOM 순서를 유지
- 캡처 원본은 `design/review/2026-10-23/`에 둡니다.
- 단일 이미지는 4:3 대형 카드로, Room·Shelf 공유 버튼은 헤더 우측으로 배치해 캡처로 확인했습니다.

## 6. 남은 작업

- 토스트 퇴장은 controlled `open`과 `forceMount`로 120ms `toast-out`을 재생한 뒤 제거합니다.
- AI 분석 단계 표시, Undo, 햅틱·사운드는 백엔드/제품 결정이 필요해 P2로 남깁니다.
- View Transitions는 목록→상세 링크에 적용했고, 브라우저 미지원 시 일반 이동으로 동작합니다.
- 데스크톱 검색 masonry는 빈 공간을 줄이지만 읽기 순서가 열 기준이 되므로 실제 사용성 테스트로 확인합니다.
- axe WCAG 2 A/AA 자동 검사는 홈·재고 상세·검색·등록 시트·토스트·다크 홈에서 통과했습니다.
- 실제 스크린리더(NVDA+Chrome, VoiceOver+Safari)와 200% 확대 검증은 M8 접근성 점검에서 수행합니다.
