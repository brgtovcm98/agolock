# ADR-023: 물건·재고 변경 일관성과 편집 계약

## 상태

승인됨

## 날짜

2026-10-24

## 맥락

카테고리 병합이 자원 버전을 변경하지 않고, 참조 확인 후 soft delete가 경합할 수 있었습니다. 화면 경로에는 여러 계층 ID가 있지만 저장 위치는 정확히 하나입니다. 전체 재고 수만으로 공통 정보 변경의 영향을 안내하면 일부 오버라이드를 잘못 설명합니다.

## 결정

- 화면 경로와 저장 위치를 분리하고 API에는 가장 깊은 위치 ID 하나만 전송합니다.
- 변경 트랜잭션은 Category → Item → Room → Shelf → Box → Inventory 순으로 행을 잠그며 동일 종류는 UUID 순으로 획득합니다. 대기 후 활성 여부·위치·권한을 다시 확인합니다.
- MyBatis 로컬 캐시는 STATEMENT 범위로 제한해 JDBC 잠금 후 재조회가 이전 SESSION 캐시를 사용하지 않게 합니다.
- 병합은 영향을 받는 Item·Inventory의 version을 증가시킵니다. 삭제도 필수 version과 조건부 갱신을 적용합니다.
- PATCH의 생략·null·빈 설명을 구분합니다. 폐기 확인은 DISPOSED로 전환할 때 요구합니다.
- 변경 영향은 제안된 PATCH와 version을 받아 필드별 상속과 재고 합집합을 집계합니다. 미리보기는 조회 시점의 예상치이며 저장 시점의 재고 집합을 고정하지 않습니다.
- 충돌 시 원본 필드의 기준값·입력·최신값을 비교하고 충돌 필드는 명시적으로 선택합니다. 자동 재전송하지 않습니다.
- 프론트엔드 API 타입은 실제 구현에서 생성한 승인 OpenAPI 스냅샷으로 생성합니다. 설계 초안은 계속 보존합니다.
- 기존 카테고리 정규화에서 활성 이름 충돌이 있으면 마이그레이션을 중단하며 자동 병합하지 않습니다.

## 결과

생성과 삭제, 병합과 편집 사이의 경쟁을 제어하고 입력 소실과 계약 불일치를 줄입니다. 잠금으로 같은 자원 변경이 대기할 수 있으며, 기존 API 소비자는 삭제 version과 새 미리보기 계약에 맞춰 갱신해야 합니다.

## 대안

- 애플리케이션 사전 검사만 유지: soft delete 경합을 막을 수 없어 제외했습니다.
- Space 전체 쓰기 직렬화: 불필요한 자원 사이의 대기를 피하기 위해 선택하지 않았습니다.
- 수정 충돌 시 폼 초기화: 사용자 입력 보존 요구와 맞지 않아 제외했습니다.
