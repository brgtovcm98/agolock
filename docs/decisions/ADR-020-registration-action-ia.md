# ADR-020: 등록 행동 중심 정보 구조

- 상태: 승인됨
- 날짜: 2026-10-21

## 맥락

M3 구현 당시 `/inventory`는 카테고리 생성, Item 생성, Inventory 생성을 한 화면에 쌓아 둔 관리 콘솔이었습니다. 이 화면은 다음 문제를 만들었습니다.

- 사용자가 "물건 하나를 등록"하려면 최대 세 번 저장하고 Item과 Inventory의 차이를 먼저 이해해야 합니다.
- 등록 위치를 Room 드롭다운에서 다시 찾아야 하며, Room·Shelf·Box 상세 화면에서는 해당 위치에 등록할 수 없습니다.
- 앱 셸과 모바일에 상시 등록 진입점이 없어 핵심 행동이 재고 탭 안쪽에 묻힙니다.
- 등록 후 이동할 재고 상세·물건 상세 화면이 없어 등록이 막다른 길이 됩니다.
- 홈은 검색과 최근 항목 대신 마일스톤 체크리스트를 보여 줍니다.

이 문제는 화면을 더 추가하는 것으로 해결되지 않습니다. 사이트맵이 엔티티별 CRUD를 기준으로 나뉘어 있어, 사용자의 행동 단위 흐름이 만들어지지 않기 때문입니다.

## 결정

- 등록은 목적지 화면이 아니라 모든 화면에서 열 수 있는 행동으로 둡니다.
- 위치 문맥을 주 진입점으로 사용합니다. Room·Shelf·Box 상세의 "이 위치에 등록"은 위치를 미리 채우고, 전역 등록은 위치를 선택합니다.
- 등록은 하나의 시트에서 처리하며, 사진·이름·위치를 먼저 받고 카테고리·가격·설명·재고별 예외 값은 점진적으로 펼칩니다.
- 사용자 화면에서는 `Item`·`Inventory` 대신 "물건"과 "같은 물건의 재고 N개"를 사용합니다. `Item`·`Inventory`는 내부 용어로 유지합니다.
- 새 물건과 기존 물건에 재고 추가를 한 시트의 두 모드로 제공합니다. 새 물건 생성은 소유자만 가능하고, 공유 `MANAGE` 사용자는 기존 물건 모드만 사용합니다.
- 카테고리 관리는 설정에 두고, 등록 시트에서는 소유자에게 검색형 선택과 인라인 생성을 제공합니다.
- 1차에서 재고는 개별 물건 단위를 유지합니다. 같은 물건을 여러 개 등록할 때는 "계속 등록"으로 폼을 유지하고 수량 필드를 도입하지 않습니다.
- 등록 후에는 위치 경로와 함께 "계속 등록", "물건 보기"를 제공하고, 재고 상세·물건 상세를 수정·이동·재등록의 허브로 사용합니다.
- 모바일은 5개 하단 탭을 유지하고 등록은 FAB로 띄웁니다. 홈은 검색과 최근 추가를 우선합니다.
- M5 이미지·M7 AI 입력 전까지 P0 등록 시트는 이름·위치·카테고리·가격·설명·상태를 다룹니다. 사진과 AI 제안은 같은 시트의 앞 단계에 후속으로 붙입니다.

## 결과

- 등록 횟수가 줄고, 위치를 기억해 다시 선택하는 단계가 사라집니다.
- 사용자가 도메인 개념을 배우지 않고도 등록할 수 있습니다.
- 등록 후 상세 화면으로 이어져 수정·이동·재등록이 가능해집니다.
- 재고 상세·물건 상세·목록·위치 상세를 함께 구현해야 하므로 초기 화면 범위가 늘어납니다.
- 새 물건과 첫 재고 생성은 현재 API에서 두 번의 호출이 필요합니다. 서버의 `newItem` 통합 생성이 준비되기 전까지 클라이언트가 실패 복구를 책임집니다.
- 사진·AI가 빠진 P0와 최종 폼 사이에 시각적 차이가 남습니다. M5·M7에서 같은 시트에 단계를 추가합니다.

## 대안

- `/inventory` 관리 콘솔을 유지하고 폼만 정리: 화면 수는 적지만 등록이 계속 목적지가 되고 위치 문맥이 남지 않습니다.
- 별도 3단계 위저드: 단계가 명확하지만 빠른 등록에서 이탈이 늘고, 위치 문맥 진입과 결합하기 어렵습니다.
- 전역 등록만 제공: 구현은 단순하지만 "지금 이 박스에 넣는다"는 현장 흐름을 잃습니다.
- 수량 필드 도입: 도메인의 개별 재고 원칙과 충돌하고 이동·상태·이력 모델을 다시 설계해야 합니다.
