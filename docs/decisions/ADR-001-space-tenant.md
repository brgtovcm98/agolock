# ADR-001: Space 테넌트 경계와 공유 스키마

- 상태: 승인됨
- 날짜: 2026-10-19

## 맥락

개인 물품 관리 앱은 사용자별 데이터 격리와 Room/Shelf 공유를 동시에 지원해야 합니다. 공유는 다른 사용자의 Space에 접근하는 예외이므로, 격리와 공유를 함께 다룰 수 있는 테넌트 모델이 필요합니다.

## 결정

- Space를 테넌트 경계로 사용합니다.
- 사용자 가입 시 개인 Space를 하나 생성합니다.
- 모든 테넌트 데이터는 `space_id`를 가집니다.
- 공유 DB와 공유 스키마를 사용합니다.
- 같은 Space 안에서만 참조하도록 복합 FK를 사용합니다.
- 접근 제어는 애플리케이션 `AccessService`가 담당합니다.
- PostgreSQL RLS는 2차 방어선으로 추가할 수 있습니다.

## 결과

- 공유를 테넌트 경계의 예외 접근으로 일관되게 모델링할 수 있습니다.
- 마이그레이션과 운영이 단순합니다.
- 모든 테넌트 쿼리에 `space_id` 또는 ACL 조건이 필요합니다.
- 복합 FK와 인덱스 설계가 중요해집니다.
- 교차 테넌트 접근 테스트가 필수입니다.

## 대안

- Space별 PostgreSQL 스키마: 공유 시 cross-schema 권한과 마이그레이션이 복잡합니다.
- Space별 DB: 소규모 서비스에 과도하고 공유 구현이 어렵습니다.
- RLS 우선 적용: 공유 상속 정책이 복잡해 초기 구현 비용이 큽니다.
