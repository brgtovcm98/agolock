# ADR-012: 임베딩 모델과 차원 버전 관리

- 상태: 승인됨
- 날짜: 2026-10-20

## 맥락

이미지 유사도 검색은 Gemini 멀티모달 임베딩을 사용합니다. 최종 모델과 차원은 벤치마크 후 확정한다고 되어 있지만, pgvector 컬럼 차원과 HNSW 인덱스는 스키마에 고정됩니다. 또한 provider 장애 시 다른 임베딩 모델로 fallback하면 서로 다른 벡터 공간이 섞여 검색 결과가 무효가 됩니다.

## 결정

- 1차 스키마는 `vector(1408)`과 단일 임베딩 모델을 고정합니다.
- 임베딩 모델 이름과 버전을 모든 벡터와 함께 저장합니다.
- 이미지 검색은 현재 설정된 모델·버전과 일치하는 벡터만 대상으로 합니다.
- 임베딩 provider 장애 시 같은 모델로 재시도하며, 다른 모델로 fallback하지 않습니다.
- 인식 provider의 fallback은 허용합니다.
- 모델이나 차원을 바꿀 때는 기존 컬럼을 직접 변경하지 않습니다. 새 임베딩 테이블 또는 새 컬럼을 만들고 백필한 뒤 새 인덱스를 교체합니다.
- `item.embedding`은 마스터 대표 사진의 기준 벡터입니다.
- `inventory.effective_embedding`은 재고 대표 사진이 있으면 재고 벡터, 없으면 마스터 벡터를 복사해 유지합니다.
- 마스터 대표 사진이 바뀌면 자체 대표 사진이 없는 Inventory에 대해 재임베딩 fan-out job을 등록합니다.

## 결과

- 검색 인덱스와 벡터 공간의 일관성이 보장됩니다.
- 모델 변경은 재임베딩과 인덱스 교체를 포함하는 별도 마이그레이션입니다.
- 마스터 임베딩 변경 시 여러 Inventory를 갱신하는 비동기 작업이 필요합니다.
- 임베딩 실패는 이미지 검색에서만 제외하고 재고 저장은 막지 않습니다.

## 대안

- 차원을 미정으로 두고 구현 후 결정: 마이그레이션과 인덱스 생성이 불가능합니다.
- provider fallback으로 다른 모델 사용: 벡터 공간이 섞여 유사도 검색이 깨집니다.
- Inventory마다 조인으로 마스터 벡터 참조: HNSW 인덱스를 직접 사용할 수 없습니다.
