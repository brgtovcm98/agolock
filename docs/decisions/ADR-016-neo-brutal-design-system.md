# ADR-016: E안 네오 브루탈 디자인 시스템 채택

- 상태: 승인됨
- 날짜: 2026-10-20

## 맥락

[화면과 흐름](../frontend.md)은 화면 목록과 사용자 흐름의 단일 원본이지만 시각 표현은 정의하지 않습니다. 디자인 후보 A(Archive), B(Soft Home), C(Blueprint), D(shadcn 기본형), E(Neo-Brutal)를 비교한 뒤 E안을 채택했습니다. E안은 두꺼운 테두리, 블러 없는 하드 섀도, 평면색, Noto Sans KR 단일 서체를 사용합니다.

M1부터 화면을 계속 추가하므로 토큰, 컴포넌트 규격, 다크 모드, 서체 로딩, 접근성 기준을 먼저 고정해야 화면마다 스타일이 갈라지지 않습니다.

## 결정

- E안 네오 브루탈리즘을 프론트엔드 시각 시스템으로 채택합니다.
- 색·간격·형태·타이포그래피는 `frontend/src/styles/globals.css`의 CSS 변수와 Tailwind 4 `@theme inline`으로 정의합니다.
- 라이트·다크는 `.dark` 클래스로 전환하고, 시스템 설정을 기본값으로 하며 사용자의 수동 선택을 `localStorage`에 저장합니다.
- Noto Sans KR 500/700/900을 `@fontsource/noto-sans-kr`로 셀프 호스팅합니다.
- 모서리 반경은 0, 기본 테두리는 2.5px, 카드 섀도는 5px, 버튼 섀도는 4px로 고정합니다.
- 칩·상태·뱃지·오버라이드는 높이 28px, 12px/700, 좌우 10px, 테두리 2px의 단일 규격을 사용합니다.
- 상태는 색만으로 구분하지 않고 `사용중`, `보관`, `폐기` 텍스트를 함께 표시합니다.
- 시각 규칙과 화면별 요소의 단일 원본은 [디자인 시스템](../design-system.md)입니다.
- M0에서는 3개 시안을 `/design-preview`에서 목데이터로 재현해 토큰과 반응형 규칙을 검증합니다.

## 결과

- 새 화면은 같은 토큰과 컴포넌트로 빠르게 만들 수 있습니다.
- 외부 폰트 CDN에 의존하지 않으며 오프라인 PWA 요건과 개인정보 측면에서 유리합니다.
- 주요 색 조합은 WCAG AA 명암비를 충족합니다.
- 미설계 화면 9개와 로딩·오류 상태는 각 마일스톤에서 디자인을 확장해야 합니다.
- 시안 미리보기 코드는 제품 기능이 아니며 M1 이후 실제 화면으로 대체됩니다.

## 대안

- A안 Archive: 모노스페이스 병용과 종이 라벨 컨셉이 정보 밀도에는 유리하지만 모바일 가독성이 떨어집니다.
- B안 Soft Home: 친근하지만 상태·권한 정보가 약해집니다.
- C안 Blueprint: 다크·네온 중심이라 라이트 모드와 접근성 대응 비용이 큽니다.
- D안 shadcn 기본형: 구현은 빠르지만 제품 고유의 시각 정체성이 없습니다.
- Google Fonts CDN: 설정이 간단하지만 외부 의존과 개인정보 문제가 있습니다.
