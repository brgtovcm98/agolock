# ADR-014: 설계 단계 생성 문서 운영

- 상태: 승인됨
- 날짜: 2026-10-20

## 맥락

`docs/generated/` 아래 OpenAPI, 이벤트, 데이터 사전은 생성물로 분류되어 직접 수정하지 않는 규칙을 따릅니다. 그러나 아직 백엔드 코드와 생성기가 없어 설계 결정을 계약 문서에 반영할 방법이 없습니다. 생성기를 먼저 만들려면 구현 코드가 필요하므로 문서 단계에서 순환이 생깁니다.

## 결정

- 구현 착수 전까지 `docs/generated/`의 세 문서는 "설계 초안"으로 취급합니다.
- 설계 단계에서는 결정을 반영하기 위해 세 문서를 수동으로 갱신할 수 있습니다.
- 각 문서 머리말에 설계 초안 상태와 생성기 대체 예정을 표시합니다.
- 구현 착수 시 springdoc OpenAPI, 스키마 introspection 데이터 사전, 이벤트 스키마 export 생성기를 만듭니다.
- 생성기가 준비되면 generated 문서는 다시 직접 수정 금지 대상이 되고, 생성 결과와 설계 문서의 차이를 검사합니다.
- `scripts/docs_check.py`는 생성기 도입 후 generated 머리말과 생성 명령을 검사하도록 확장합니다.
- M0에서는 [ADR-015](ADR-015-contract-preview-mode.md)에 따라 생성 결과를 `build/contracts/`에만 기록하고 `docs/generated/` 설계 초안을 보존합니다.

## 결과

- 문서 단계에서 계약을 최신 결정과 일치시킬 수 있습니다.
- 일시적으로 generated 문서가 수동 관리되므로 코드와의 자동 동기화는 보장되지 않습니다.
- 구현 착수 시 생성기 도입을 완료 조건으로 삼아야 합니다.

## 대안

- generated 문서를 지금 수정하지 않음: 계약과 설계 문서가 불일치합니다.
- 설계 전용 별도 문서를 만들고 generated는 비워 둠: 단일 원본이 둘로 나뉩니다.
- 구현 전에 생성기를 먼저 작성: 백엔드 스키마와 코드가 없어 불가능합니다.
