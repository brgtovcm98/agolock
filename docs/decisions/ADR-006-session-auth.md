# ADR-006: 이메일+비밀번호와 세션 쿠키

- 상태: 승인됨
- 날짜: 2026-10-19

## 맥락

초기에는 OAuth 없이 이메일과 비밀번호로 가입·로그인해야 합니다. 스테이징 환경은 초대코드로 가입을 제한합니다. 웹과 PWA에서 안전하게 세션을 유지해야 합니다.

## 결정

- 이메일과 비밀번호로 인증합니다.
- 비밀번호는 Argon2id로 해시합니다.
- 스테이징 가입은 초대코드를 요구합니다.
- 세션은 서버 세션과 HttpOnly, SameSite=Lax 쿠키를 사용합니다. 운영에서는 Secure를 필수로 합니다.
- 세션 저장소는 Spring Session JDBC를 사용합니다.
- 상태 변경 요청은 CSRF 토큰으로 보호합니다.
- 로그인과 초대코드 검증에 레이트리밋을 적용합니다.
- OAuth는 3차 이후 추가합니다.

## 결과

- 세션 강제 만료와 로그아웃이 단순합니다.
- JWT refresh rotation과 토큰 저장 문제를 피할 수 있습니다.
- 서버 세션 테이블과 CSRF 처리가 필요합니다.
- 모바일 네이티브 앱이 생기면 토큰 기반 인증을 별도로 검토해야 합니다.

## 대안

- JWT access/refresh: 모바일·외부 API에 유리하지만 회전과 폐기 구현이 복잡합니다.
- Redis 세션: 확장에는 유리하지만 A0 규모에서는 컴포넌트가 늘어납니다.
- OAuth 우선: 초기 요구와 맞지 않고 provider 설정이 필요합니다.
