# ADR-003: 누적 권한 모델

- 상태: 승인됨
- 날짜: 2026-10-19

## 맥락

Room과 Shelf 공유는 보기, 수정, 재고 추가·삭제의 3단계를 요구합니다. Room Grant와 Shelf Grant가 동시에 존재할 수 있고, 상위·하위 Grant가 겹칠 수 있습니다.

## 결정

- 권한은 `VIEW < EDIT < MANAGE` 누적 구조로 정의합니다.
- `EDIT`는 재고 오버라이드, 사진, 상태 수정을 포함합니다.
- `MANAGE`는 `EDIT`를 포함하고 재고 추가·삭제·이동을 허용합니다.
- 소유자는 `OWNER`로 모든 권한을 가집니다.
- 여러 Grant가 있으면 가장 높은 권한을 적용합니다.
- Room Grant와 Shelf Grant는 동시에 유지하며, 철회 시 나머지 Grant로 재계산합니다.
- 거부(deny) 규칙은 MVP에서 지원하지 않습니다.
- 마스터 공통 필드, 계층, 카테고리, 공유 관리는 소유자만 가능합니다.

## 결과

- UI와 API가 3단계로 단순해집니다.
- 권한 상승 사고를 줄일 수 있습니다.
- 공유 사용자가 마스터를 수정하지 못해 다른 재고에 미치는 영향을 제한합니다.
- 선반별 비공개 예외는 3차까지 지원하지 않습니다.

## 대안

- 독립 비트 권한: 유연하지만 UI와 검증이 복잡해집니다.
- 상위 Grant가 하위 Grant를 덮어쓰기: 이미 공유된 Shelf의 권한을 의도치 않게 낮출 수 있습니다.
- 최신 Grant 우선: 순서에 따라 권한이 달라져 예측이 어렵습니다.
